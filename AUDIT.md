## 1. App architecture

### 1.1 Tech stack
| Layer | Technology |
|---|---|
| UI | Flutter (Dart, about 143 files and about 47k lines), Material, Lottie, tutorial_coach_mark, Flame + flame_forge2d (Carrom, Love Physics) |
| State / DI | `provider`. A MultiProvider in `lib/main.dart` registers 8 global providers. Only AuthService, UnreadManager, SignalingService and AstrologyViewModel are ever read. PresenceService, DatabaseService, FirestoreManager and CallService are lazy and never read, so they are never constructed. Most screens use `setState` and call Firebase directly. HomeScreen is the only one with a controller (`HomeController`). |
| Auth | Firebase Auth: email/password and Google Sign-In |
| Database | Cloud Firestore (profiles, chat, games). Firebase Realtime Database (call signalling). Firestore persistence is on with an UNLIMITED cache. RTDB persistence is on. |
| Backend | Cloud Functions (`functions/index.js`, Node). Two callables: `sendChatPush` and `sendCallPush`. They call the OneSignal REST API using `defineSecret('ONESIGNAL_REST_API_KEY')`. |
| Push | OneSignal is the live path (external_id = Firebase uid, set from the client via `OneSignal.login`). A second FCM stack (token sync in 3 places, onMessage and background handlers) is still wired up, but the server never sends to it. |
| Media | Cloudinary unsigned upload presets with public delivery URLs (chat images, voice notes, profile images). DiceBear HTTP API for avatars. |
| Calls | flutter_webrtc. Three singletons chained through factories: `CallService -> WebRTCService -> SignalingService`. ICE uses public shared openrelay TURN credentials. |
| Location | geolocator (the "Use Current Location" button) and geocoding (turns the questionnaire's free-text city into coordinates). `location` is declared but unused. |
| Other | Crashlytics (ErrorHandler), shared_preferences (filters, tour flags), audioplayers, record, permission_handler, image_picker. Declared but unused: google_mlkit_translation, wakelock_plus, uuid, google_fonts, badges, confetti, device_info_plus. |
| Rules / config in repo | `firebase.json` declares only `flutter` and `functions`. There are **no** firestore.rules, database.rules.json, storage.rules or firestore.indexes.json in the repo. |

### 1.3 Data model

**Firestore**
| Collection / doc | Key fields (as written by the client today) |
|---|---|
| `users/{uid}` | uid, email, username (defaults to the email prefix), `dob` ('dd/MM/yyyy' string) **and** `dateOfBirth` (ISO string or Timestamp) **and** `age`, birthTime, `location` (birth place, later overwritten by current city), sunSign/zodiacSign, gender, `discoveryEnabled`, `online`, lastSeen, profileImage, `userLatitude`/`userLongitude` (high accuracy), `fcmTokens`, notificationSettings, passwordChangedAt, avatar properties (`avatarImageUrl`), questionnaire answers (hereFor, height, bodyType, education, relationshipStatus, pets, music…), astrology answers (preferredSigns, believesInAstrology label, vibe, sleepSchedule…), signupCompleted, mandatoryCompleted, profileCompletionPercentage, matchPercentage (read, never written) |
| `conversations/{autoId}` | `participants` (sorted uids), `participantData.{uid}` {unreadCount, status, hasReplied, muted, clearedBefore, lastReadAt}, `statePerUser.{uid}` ('active' / 'new' / 'deleted'), legacy top-level `unreadCount` and `muted` maps, `isTyping.{uid}` (bool), duplicated summary fields lastMessageText/lastMessage, lastMessageAt/lastMessageTime, lastMessageSender/lastMessageSenderId |
| `conversations/{id}/messages/{id}` | senderId, receiverId, message, type (text/image/audio), mediaUrl, mediaDuration, mediaSize, timestamp, status (sent/read; 'delivered' is never written), readAt, isDeleted, editedAt, replyToMessageId |
| `ludo_queue/{uid}` | uid, playerCount, displayName, avatar, createdAt |
| `ludo_matches/{id}` (+ `chat` subcollection) | players {uid: color, displayName, avatar, status}, activeColors, maxPlayers, state (waiting/playing/finished), turnColor, turnStartedAt, dice, pawnSteps, winners, finishReason, forfeitDeadline |
| `carrom_queue/{uid}`, `carrom_matches/{id}` | players, host, status (ready/started/finished), boardState, lastMove {fromUid, ts, …}, scores, turn |
| `user_game_stats/{uid}/games/carrom`, `carrom_history/{matchId}`, `leaderboards/carrom/*/{uid}` | totalGames, wins, rank, score (each client increments its own values) |

**Realtime Database**
| Path | Content |
|---|---|
| `incoming_calls/{calleeUid}/{callId}` | callerId, callerName, callerAvatar, callType, status ('ringing'), timestamp. The caller writes it. It is only removed when the callee accepts or rejects. |
| `rooms/{callId}` | state, offer, answer, caller_candidates, callee_candidates. Rooms are never deleted. callId = `callerUid_calleeUid_millis`. |

**External integrations:** OneSignal (callable Functions to the REST API, external_id alias), FCM (tokens stored but not used), Cloudinary (unsigned presets, folders `chat_media/{convId}`, voices, profile images), DiceBear avatars API, openrelay TURN, Google Sign-In, platform geocoding, Crashlytics.

### 1.4 Navigation flow
Every screen navigates with imperative `Navigator.push`. There are no named routes, no shell or tab scaffold, and no PopScope on onboarding or call screens.
```
Splash (2s timer, plus a CTA that does the same thing)
 ├─ currentUser != null ──> HomeScreen          (profile completeness is never checked)
 └─ else ─────────────────> Login
        ├─ email login ───> HomeScreen
        ├─ Google login ──> HomeScreen          (skips all onboarding)
        └─ push Signup ─pushReplacement─> Questionnaire ─> AvatarPreview ─> PostSignupQuestions ─push─> VoiceIntro ─> HomeScreen
HomeScreen (Stack: Lottie bg, search bar + bell + hamburger/endDrawer, bubble strip, 2-col ProfileCard grid, floating CustomBottomNav)
 ├─ card tap ─> ChatScreen (creates the conversation on open) ─> Audio/VideoCallScreen
 ├─ card long-press ─> ProfileQuickSheet
 ├─ nav: Discover (DiscoverySettings) / Chats (ChatListScreen) / Games (GameListScreen) / Profile (ProfileScreen -> Edit, Astrology flow, Settings)
 └─ drawer: Discovery, My Profile, Astrology, Help, Tutorial, Sign out
Global: AvailChatApp listens on incoming_calls/{me} (onChildAdded) and pushes IncomingCallScreen only while the app is resumed.
Games: GameListScreen -> LudoLobby -pushReplacement-> LudoWrapper | CarromLobby -> CarromMatch -> CarromGame -> CarromResult
```

| ID | Sev | Depends on |
|---|---|---|
| DEST-001 | Critical | Current console rules. If they are test-mode or `request.auth != null`, any user can read every chat, rewrite any message (including forging harassment evidence), impersonate callers and edit any profile field (including future coin or premium fields). |

### 4.3 Recommendations
1. **Today (owner):** rotate the OneSignal REST key (DEST-007). Open the Firebase console and record the current Firestore, RTDB and Storage rules. If they are test mode, deploy a temporary lockdown (signed-in, participant-scoped) immediately (DEST-001).
2. Keep all rules and indexes in the repo, register them in firebase.json, deploy from CI, and test them with the Firebase emulator rules unit tests.
3. Split public and private profile data (DEST-002). Never send raw coordinates, DOB, email or tokens to other users.
4. Turn on App Check for Firestore, RTDB, Storage and Functions, restrict API keys, and enable Auth abuse protection (DEST-112, DEST-051).
5. Turn on OneSignal Identity Verification with a JWT minted by a Function (DEST-008). Keep message content out of push payloads until then.
6. Move trust-sensitive writes server-side: push triggers, game results, leaderboards, account deletion, signed media uploads, TURN credentials.
7. Build the safety baseline before launch: working block and report, 18+ gate, email verification, account deletion, call consent.
8. Add secret scanning (gitleaks pre-commit and CI), use kDebugMode-only logging, use release signing, and set allowBackup=false.
9. Before adding coins or premium: keep server-owned fields in docs only Functions can write, and use field allow-lists on user docs.
